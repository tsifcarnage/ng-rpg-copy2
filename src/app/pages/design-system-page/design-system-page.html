Chapitre 02

Le problème

Avant de copier des recettes, comprends pourquoi le refactoring existe. Trois idées suffisent.

①

La duplication coûte cher

La même couleur rgba(21, 163, 8, …) vivait dans 5 fichiers. Changer le vert, c’était 5 retouches — et 5 occasions d’en oublier une. Le code dérive, les écrans ne se ressemblent plus.

Règle DRY — Don’t Repeat Yourself : chaque décision n’existe qu’à un seul endroit.

②

Une source unique de vérité

On déplace la décision (« le vert succès ») vers un token, et la structure (« le carré à icône ») vers un mixin. Les composants ne décrivent plus comment, ils réclament : var(--success), @include icon-badge().

Modifier la source → tout l’écran suit. C’est le levier de cohérence.

③

Deux couches, deux portées

Angular encapsule le CSS de chaque composant (il est isolé). Mais les variables CSS posées sur :root traversent cette barrière : tout composant voit var(--accent) sans rien importer.

Tokens = globaux, zéro import. Mixins = compilés, à @use par fichier.

⚗️ Avant · plomb
  • couleurs rgba() recopiées dans 5 fichiers
  • 8 lignes identiques pour chaque tuile d’icône
  • une retouche = la refaire partout, à la main
  • font-size: smaller au hasard des fichiers
→
✨ Après · or
  • 0 couleur en dur — tout passe par un token
  • @include icon-badge() en une ligne
  • une retouche au mixin → propagée d’un coup
  • une échelle --text-* unique et cohérente

Chapitre 07

Étendre le système

Un jour tu auras besoin d’une couleur ou d’un motif qui n’existent pas encore. Voici les deux recettes — suis-les pour rester cohérent avec le reste.

Recette A

Ajouter une couleur sémantique

Objectif : un statut « poison » 🐍, vert acide, réutilisable partout.

  1. 1

    Déclare le triplet de canal dans :root (styles.scss).

    --poison-rgb: 132, 204, 22;
  2. 2

    Décline les variantes standard à partir du triplet — comme les autres familles.

    --poison: #84cc16;
--poison-soft: rgba(var(--poison-rgb), 0.14);
--poison-border: rgba(var(--poison-rgb), 0.5);
--poison-glow: rgba(var(--poison-rgb), 0.25);
--poison-text: #d4f7a0;
  3. 3

    Consomme-la, sans jamais réécrire le rgba() en dur.

    .tag-poison {
  @include pill(
    var(--poison-text),
    var(--poison-soft),
    var(--poison-border)
  );
}
Recette B

Ajouter un mixin

Indice : tu copies-colles la même structure une 2ᵉ fois ? C’est le signal.

  1. 1

    Repère ce qui se répète, isole ce qui varie → ce seront les $arguments.

  2. 2

    Déclare-le dans _mixins.scss avec des valeurs par défaut.

    @mixin chip-stat($color: var(--accent)) {
  display: inline-flex;
  align-items: center;
  gap: 0.3rem;
  color: $color;
  font-variant-numeric: tabular-nums;
}
  3. 3

    Remplace chaque copie par un @include, puis vérifie d’un grep qu’il n’en reste plus.

    .atk { @include chip-stat(var(--danger)); }
.def { @include chip-stat(var(--info)); }

Le réflexe : une valeur en dur ou une structure copiée une 2ᵉ fois → arrête-toi et factorise. Mieux vaut un token de plus qu’une dérive de plus.
